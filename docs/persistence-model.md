# Persistence Model

## 1. Principles

- PostgreSQL is the canonical source of truth.
- Ownership is carried on every top-level resource and included in queries.
- Append-only response runs and stream events preserve lifecycle history.
- Mutable message content is allowed only while the assistant message is partial; terminal content is immutable.
- Database constraints enforce idempotency and one active run.

## 2. Tables

### `conversations`

| Column | Meaning |
|---|---|
| `id uuid primary key` | Canonical conversation ID |
| `user_id text not null` | Authenticated owner identifier |
| `title text not null` | Display title |
| `created_at`, `updated_at timestamptz` | Ordering/audit |
| `archived_at timestamptz null` | Soft archive |

Indexes: `(user_id, updated_at desc, id desc)` and `(user_id, archived_at)`.

### `messages`

| Column | Meaning |
|---|---|
| `id uuid primary key` | Canonical message ID |
| `conversation_id uuid references conversations` | Parent |
| `role text check in ('user','assistant')` | Speaker |
| `content text not null` | Canonical Markdown text |
| `status text` | `complete`, `partial`, `cancelled`, or `failed` |
| `client_message_id uuid null` | Client reconciliation key for user messages |
| `in_reply_to_id uuid null references messages` | User message answered by an assistant message |
| `version integer not null default 1` | Regenerated answer number |
| `is_visible boolean not null default true` | Active answer version |
| `created_at`, `updated_at timestamptz` | Ordering/audit |

Constraints:

- Unique `(conversation_id, client_message_id)` where `client_message_id is not null`.
- Unique visible assistant answer per `in_reply_to_id` through a partial unique index.
- Role-dependent columns are checked: user messages require `client_message_id` and `status='complete'`; assistant messages require `in_reply_to_id`.
- Foreign keys to `conversations` and parent messages use `ON DELETE RESTRICT`. Product archive never deletes rows in V1. A future deletion phase will delete in order: events → runs → messages → conversations, then diagnostic stores.
- Canonical IDs (conversation, message, run, event) are UUIDv7 generated by the server. `client_message_id` and `Idempotency-Key` are client-generated UUID strings (v4 or v7 accepted).

### `response_runs`

| Column | Meaning |
|---|---|
| `id uuid primary key` | Response attempt |
| `conversation_id uuid not null references conversations on delete restrict` | Parent conversation |
| `user_id text not null` | Owner; denormalized for the per-user active-run cap |
| `user_message_id uuid not null references messages on delete restrict` | Prompt turn |
| `assistant_message_id uuid not null references messages on delete restrict` | Produced answer |
| `status text` | Run state machine value |
| `attempt integer` | Retry/regeneration attempt number |
| `provider`, `model text` | Audit dimensions, not secrets |
| `last_sequence bigint not null default 0` | Latest committed event |
| `cancel_requested_at timestamptz null` | Cross-replica cancellation signal |
| `owner_instance_id uuid null` | API process that supervises generation |
| `lease_expires_at timestamptz null` | Generation ownership lease; expired leases are recoverable as orphans |
| `started_at`, `completed_at timestamptz null` | Lifecycle timing |
| `error_code`, `diagnostic_id text null` | Safe categorization |
| `input_tokens`, `output_tokens bigint null` | Usage |
| `created_at`, `updated_at timestamptz` | Audit |

A partial unique index on `conversation_id` for non-terminal statuses enforces one active run per conversation. Index `(user_id) where status not in ('completed','cancelled','failed')` supports the cap query inside the advisory lock. `user_id` must match `conversations.user_id`.

### `stream_events`

| Column | Meaning |
|---|---|
| `run_id uuid references response_runs` | Run |
| `sequence bigint` | Per-run cursor |
| `event_id uuid unique` | Diagnostic/deduplication ID |
| `type text` | Event discriminator |
| `payload jsonb` | Versioned event data only |
| `occurred_at timestamptz` | Event time |

Primary key: `(run_id, sequence)`. Index `(run_id, sequence)` is naturally provided by the key.

### `idempotency_records`

| Column | Meaning |
|---|---|
| `user_id text` | Scope |
| `operation text` | Endpoint operation |
| `key uuid` | Request key |
| `request_hash text` | Detect mismatched reuse |
| `resource_id uuid` | Existing conversation/run |
| `created_at`, `expires_at timestamptz` | Retention |

Primary key: `(user_id, operation, key)`.

## 3. Transaction boundaries

### Create turn

One transaction locks the conversation (and takes a per-user advisory lock `pg_advisory_xact_lock(hashtext(user_id))`), verifies ownership, no active run on the conversation, and `count(non-terminal runs for user_id) < MAX_ACTIVE_RUNS_PER_USER`, inserts or finds the user message, creates the assistant placeholder and `queued` run, **stamps `owner_instance_id` and `lease_expires_at = now() + LEASE_SECONDS` on that run in the same transaction**, stores the idempotency result, and if this is the first user message and `title = 'New conversation'`, sets `title` to the trimmed content clipped to 80 characters. The supervisor may renew the lease; it must not be the first writer of the lease. Non-terminal rows with `lease_expires_at IS NULL` are treated as expired.

### Append delta

One transaction locks the run, checks cancellation/terminal state, appends to assistant content, increments `last_sequence`, and inserts the matching event. Readers never observe content ahead of its event cursor.

### Complete or fail

One transaction writes final message content/status, terminal run fields, usage/error metadata, the terminal event, and conversation `updated_at`.

### Retry or regenerate

Terminal assistant content is immutable, so both retry (from `failed`/`cancelled`) and regenerate (from `completed`, also allowed from `failed`/`cancelled`) reuse the **create-turn invariants** in one transaction: per-user advisory lock, conversation lock, archived check, no active run on the conversation, per-user cap, hide previous visible assistant, insert new visible assistant (`version = previous + 1`, `status=partial`, empty content), insert `queued` run with `user_id` and lease columns stamped, record idempotency. On creation failure, the previous version remains visible.

Retry is rejected with `invalid_run_state` when the source run is not `failed` or `cancelled`. Regenerate is rejected with `conversation_busy` when a run is already active on the conversation.

## 4. Retention and privacy

- Conversation/message retention follows product policy. **V1 archive is not deletion.** User-deletion APIs, backup purge, and telemetry purge are a later privacy phase; observability and security docs describe the obligation that phase must meet, not a V1 endpoint.
- Stream events may be compacted after the operational replay window once a terminal snapshot exists.
- Idempotency rows expire after the maximum client retry window, never while their run is active.
- Logs do not contain message content by default; the database contains content and requires encryption at rest plus access controls.

## 5. Migration discipline

Use forward-only, reviewed migrations with additive schema changes first. Deploy code that tolerates old/new schema during rollout, backfill separately, then enforce new constraints. Every destructive migration requires a backup/restore rehearsal and explicit later approval.
